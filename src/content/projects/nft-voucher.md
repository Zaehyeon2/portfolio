## 배경 및 목표

플랫폼 산하의 게임사가 “유저가 보유한 교환용 NFT(Voucher)를 이에 대응하는 새로운 게임 아이템 NFT를 보상으로 교환해주는 기능”을 요청.

→ 교환용 NFT(Voucher)를 소각(Burn)하는 이벤트를 실시간으로 감지하여, 이에 대응하는 미공개(밀봉된) 게임 아이템 NFT를 무작위 스펙으로 발행(Mint)해주는 E2E(End-to-End) 서비스의 백엔드 아키텍처를 개발.

## 역할

시스템 구조 설계 참여 및 주도적 개발

## 주요 업무 및 성과

### ① 실시간 온체인 이벤트 리스너 및 트랙킹 (Nest.js)

- 컨트랙트에서 발생하는 바우처 NFT의 Burn 이벤트를 백엔드에서 실시간으로 감지하고 트래킹하는 이벤트 기반 파이프라인 구축.

### ② 사용자 경험(UX) 중심의 무작위 NFT 발행 로직 설계

- 기존 문제 인지: Token ID가 순차적으로 발행될 경우, 유저가 “내 결과물이 이미 정해져 있었다”고 느껴 무작위 스펙에 대한 신뢰도와 재미가 반감될 수 있는 UX적 한계 발견.
- **기술적 해결**: NFT 발급 시점에 온체 난수를 통해 Token ID 및 아이템 스펙이 동적으로 결정되도록 로직을 고도화하여 공정성과 몰입감 제공.

### ③ 탈중앙화 메타데이터 관리 (IPFS)

- NFT가 발급되는 시점에 확정된 무작위 스펙 데이터를 기반으로 메타데이터 JSON을 동적으로 생성.
- 생성된 메타데이터를 분산형 저장소인 IPFS에 보안 및 무결성을 유지하며 업로드하고 온체인 tokenURI와 매핑.

## 결과

① 성공적인 상용화: 실제 유저들이 대거 참여하는 상용 레벨의 웹3 비즈니스 모델(Voucher-to-Item)을 성공적으로 론칭하고 트랜잭션 무결성을 지키며 안정적으로 운영.

② 매출 견인: 교환용 NFT 완판 및 게임사 매출 증가에 직접적으로 기여.

## 회고

이번 프로젝트는 처음으로 외부 개발사와 소통하며 실제 유저들이 사용하는 상용 서비스를 구축해 본 뜻깊은 경험이었다. 또한 온체인 난수를 이용한 무작위 ID 발급 과정에서 발생하는 동시성 제어(Race Condition) 문제를 고려해야 했다

→ 동시 트래픽이 많은 서비스는 아니었기에 DB 내에 교환용 ID와 게임 아이템 ID의 매핑 테이블을 구축한 뒤 Minted, Burned 등 상태 관리(State Management) 로직을 적용하여 ID 선점과 발급 상태를 원자적(Atomic)으로 관리했다.
