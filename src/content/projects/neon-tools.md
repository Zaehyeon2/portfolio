## 배경 및 목표

① **장애 원인 추적의 비효율성**: 사내 OpenSearch에 플랫폼 서버 로그, Access 로그, 이벤트 로그가 축적되어 있었으나, 로그 모니터링 툴이 완전히 분리되어 있어 장애 발생 시 원인 추적이 어려웠음.

② **기술 소통 채널 부재**: 네오위즈 게임 플랫폼 NEON의 SDK를 연동해야 하는 사내 여러 게임 스튜디오의 클라이언트 개발자들이 기술적 바틀넥이나 런타임 에러를 마주했을 때, 신속하게 질의하고 해결할 수 있는 소통 채널이 부족했음.

**③ AI 생산성 도구의 한계**: Cursor, Claude Code 등 사내 개발자들이 활용하는 AI 코딩 에이전트가 회사의 폐쇄적인 내부 보안 데이터와 결합되지 못해 활용도가 제한되는 한계 직면.

④ **개발 가이드 문서 검색의 어려움:** 개발 가이드 문서가 존재하지만 SDK를 연동하는 개발자 입장에서 정보를 찾기가 어려웠음.

→ SDK Docs RAG Tool, Event Search Tool, Service/Access Log Search Tool 3대 핵심 엔진을 개발하고 이를 AI 에이전트 인터페이스(MCP, CLI, Chatbot)와 통합하여, 클라이언트 개발자들이 인적 의존성 없이 기술적 문제를 자가 해결할 수 있는 환경 구축.

## 역할

시스템 구조 설계 참여 및 주도적 개발

## 주요 업무 및 성과

### ① SDK 문서 및 소스코드 RAG Tool

- **문서의 시맨틱 청킹:** 단순 글자 수 분할을 지양하고, HTML 가이드 문서의 계층 구조 및 docfx 문법 변환 규칙을 적용하여 파싱함으로써 Anchor 및 명세를 보존하는 청킹 로직 이식.
- **컨텍스트 유실 방지 전략:** 분할된 텍스트 청크 임베딩 시 상위 부모 헤더 정보와 소속 패키지명을 메타데이터로 함께 조합하여 임베딩함으로써, LLM이 코드의 거시적 맥락을 정확히 인지하도록 유도.
- **증분 인덱싱 및 논블로킹 가동:** 파일 MD5 해시 비교 알고리즘을 도입하여 변경된 문서만 선별 처리하는 **증분 인덱싱(Incremental Indexing)** 파이프라인 구축.
- **하이브리드 검색(Hybrid Search) 알고리즘 이식**: 클래스명, API 명칭, 변수명 등 100% 일치해야 하는 키워드는 BM25 검색(가중치 0.4)이 잡아내고, 개발자의 모호한 질의어에 담긴 의미적 유사성은 Dense 벡터 검색(가중치 0.6)이 소화하도록 설계.

### ② Event Log Search Tool

- 사내 데이터 수집 시스템을 통해 OpenSearch에 적체된 실시간 이벤트 로그를 자연어로 질의·스크래핑하고 정량 분석할 수 있는 전용 컨텍스트 툴 구축.

### ③ 서버 및 Access 로그 Search Tool)

- OpenSearch 내 플랫폼 서버 및 Access 로그를 자연어로 질의·스크래핑할 수 있는 컨텍스트 툴을 구축하고, 연관된 요청의 흐름을 역추적하는 Trace Correlation(로그 추적 상관관계) 로직 탑재.

### ④ n8n 허브 기반 3대 멀티 채널(MCP · CLI · Chatbot) 통합 아키텍처 구현

- **n8n 워크플로우 오케스트레이션:** 로우코드 자동화 플랫폼 n8n을 백엔드 파이프라인 허브로 활용하여, 개발한 3대 도메인 툴(Docs, Events, Logs)을 단일 코어 로직으로 제어하는 에이전트 워크플로우 설계.
- **MCP (Model Context Protocol) 서버 표준 구현:** Claude Code, Cursor, Gemini CLI 등 현업 개발자들이 사용하는 모던 LLM 에이전트들이 사내 RAG 및 로그 검색 기능을 런타임에 ‘도구(Tools)’로서 다이내믹하게 호출할 수 있도록 MCP Spec 서버 규격 구축.
- **Go 기반 초경량 CLI 개발 및 유통:** 개발자의 로컬 머신 터미널 환경에서 단 한 줄의 셸 커맨드로 지식 문서, 이벤트 데이터, 에러 로그를 통합 탐색할 수 있는 초경량 인터페이스(neonctl) 완비.
- **대화형 Chatbot UI 릴레이:** n8n Chat Trigger UI를 연동하여 비개발자나 CLI 환경이 낯선 내부 구성원들도 웹 브라우저 상에서 자연어로 플랫폼 상태를 모니터링할 수 있는 접근성 제공.

## 결과

① **장애 대응 및 트러블슈팅 시간 혁신적 단축 예상:** 플랫폼 장애 발생 시 개발자가 여러 모니터링 툴을 전전할 필요 없이, 소스코드 명세와 서버 에러 로그, Trace 상관관계를 한 장소에서 실시간 통합 질의 및 역추적할 수 있는 환경을 마련함 (현재 상용 배포 후 현업 실무진 피드백 수렴 중).

## 회고

이번 프로젝트는 플랫폼 팀에 새로 합류한 시선에서 조직 내의 비효율적인 업무 방식을 포착하고, 이를 해결하기 위해 주도적으로 아키텍처를 설계하고 개발을 진행한 여정이었다. 오래된 코드 베이스와 거대한 레거시 서비스들로 인해 내부 온보딩조차 무거웠던 환경에서, 이 바틀넥이 전사 스튜디오의 클라이언트 개발자들에게도 똑같은 고통을 주고 있을 것이라는 공감대에서 기획을 시작했다. 인적 자원의 한계로 기술 지원 소통 채널이 마비될 수 있는 리스크를, 시스템과 도구(DevTools)가 담당자의 지식을 복제해 대체하도록 설계했다.

→ 이를 위해 SDK Docs를 검색할 수 있는 RAG 서비스를 개발하고, OpenSearch에 저장된 로그들을 탐색하는 3대 코어 툴을 만들었다. 더 나아가 n8n 오케스트레이션 허브를 주축으로 삼아 이를 MCP Spec 서버, Go 기반 CLI(neonctl), Chatbot UI라는 3대 멀티 채널 엔드포인트로 추상화함으로써, AI 에이전트를 사용하는 개발자들이 지식과 데이터에 쉽게 접근할 수 있는 최적의 개발자 경험(DX)을 완성했다.
