## 배경 및 목표

① **장애 원인 추적의 비효율성**: 사내 OpenSearch에 플랫폼 서버 로그, Access 로그, 이벤트 로그가 축적되어 있었으나 모니터링 툴이 완전히 분리되어 있어, 장애 발생 시 원인 추적이 어려웠음.

② **기술 소통 채널 부재**: 네오위즈 게임 플랫폼 NEON의 SDK를 연동하는 사내 게임 스튜디오의 클라이언트 개발자들이 기술적 바틀넥이나 런타임 에러를 마주했을 때 질의하고 해결할 소통 채널이 부족했고, 개발 가이드 문서가 있어도 정보를 찾기가 어려웠음.

③ **AI 생산성 도구의 한계**: Cursor, Claude Code 등 사내에서 쓰는 AI 코딩 에이전트가 폐쇄적인 내부 보안 데이터와 결합되지 못해 활용도가 제한됨.

→ SDK Docs RAG Tool, Event Search Tool, Service/Access Log Search Tool 3대 핵심 엔진을 개발하고 AI 에이전트 인터페이스(MCP, CLI, Chatbot)와 통합하여, 클라이언트 개발자들이 인적 의존성 없이 기술적 문제를 자가 해결할 수 있는 환경 구축.

## 역할

시스템 구조 설계 참여 및 주도적 개발

## 주요 업무 및 성과

### ① SDK 문서 및 소스코드 RAG Tool

- **시맨틱 청킹과 컨텍스트 유실 방지:** 단순 글자 수 분할 대신 HTML 가이드 문서의 계층 구조와 docfx 문법 변환 규칙을 적용해 Anchor 및 명세를 보존하는 청킹 로직 이식. 청크 임베딩 시 상위 부모 헤더와 소속 패키지명을 메타데이터로 함께 조합하여 LLM이 코드의 거시적 맥락을 인지하도록 유도.
- **증분 인덱싱(Incremental Indexing):** 파일 MD5 해시 비교로 변경된 문서만 선별 처리하는 파이프라인 구축.
- **하이브리드 검색(Hybrid Search) 알고리즘 이식**: 클래스명, API 명칭, 변수명 등 100% 일치해야 하는 키워드는 BM25 검색(가중치 0.4)이 잡아내고, 개발자의 모호한 질의어에 담긴 의미적 유사성은 Dense 벡터 검색(가중치 0.6)이 소화하도록 설계.

### ② 이벤트 · 서버 · Access 로그 Search Tool

- 이벤트 로그: 사내 수집 시스템이 OpenSearch에 적체한 실시간 이벤트 로그를 자연어로 질의·스크래핑하고 정량 분석하는 컨텍스트 툴 구축.
- 서버 · Access 로그: 플랫폼 서버 및 Access 로그를 자연어로 질의하고, 연관된 요청의 흐름을 역추적하는 Trace Correlation(로그 추적 상관관계) 로직 탑재.

### ③ n8n 허브 기반 3대 멀티 채널(MCP · CLI · Chatbot) 통합 아키텍처 구현

- **n8n 워크플로우 오케스트레이션:** 로우코드 자동화 플랫폼 n8n을 백엔드 허브로 삼아 3대 도메인 툴(Docs, Events, Logs)을 단일 코어 로직으로 제어하는 에이전트 워크플로우 설계. Chat Trigger UI를 연동해 CLI 환경이 낯선 구성원도 웹 브라우저에서 자연어로 질의할 수 있게 함.
- **MCP (Model Context Protocol) 서버 표준 구현:** Claude Code, Cursor, Gemini CLI 등 현업에서 쓰는 LLM 에이전트가 사내 RAG 및 로그 검색 기능을 런타임에 '도구(Tools)'로 호출할 수 있도록 MCP Spec 서버 규격 구축.
- **Go 기반 초경량 CLI:** 로컬 터미널에서 셸 커맨드 한 줄로 지식 문서, 이벤트 데이터, 에러 로그를 통합 탐색하는 인터페이스(neonctl) 완비.

## 결과

① **장애 대응 및 트러블슈팅 시간 단축 예상:** 장애 발생 시 여러 모니터링 툴을 전전할 필요 없이, 소스코드 명세와 서버 에러 로그, Trace 상관관계를 한 장소에서 통합 질의·역추적할 수 있는 환경을 마련함 (상용 배포 후 현업 피드백 수렴 중).

## 회고

플랫폼 팀에 새로 합류한 시선에서 조직 내의 비효율적인 업무 방식을 포착하고, 주도적으로 아키텍처를 설계하고 개발한 여정이었다. 내부 온보딩조차 무거웠던 환경에서, 이 바틀넥이 전사 스튜디오의 클라이언트 개발자들에게도 똑같은 고통을 주고 있을 것이라는 공감대에서 기획을 시작했다. 인적 자원의 한계로 기술 지원 채널이 마비될 수 있는 리스크를, 시스템과 도구(DevTools)가 담당자의 지식을 복제해 대체하도록 설계했다.

→ 이를 위해 SDK Docs를 검색하는 RAG 서비스와 OpenSearch 로그를 탐색하는 3대 코어 툴을 만들고, n8n 허브를 주축으로 MCP Spec 서버, Go 기반 CLI(neonctl), Chatbot UI라는 3대 채널로 추상화해 AI 에이전트를 쓰는 개발자들이 지식과 데이터에 쉽게 접근할 수 있게 했다.
