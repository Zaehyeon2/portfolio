## 배경 및 목표

① **수동 트러블슈팅의 비효율성**: 사내 Jira에 장애가 접수되면 개발자가 수동으로 OpenSearch에 접속하여 에러 시점의 플랫폼 서버 로그, Access 로그, 이벤트 로그를 일일이 검색하고 교차 분석해야 하는 지연이 존재했음.

→ 기존에 구축한 [Neon-tools](../neon-tools/)의 MCP 인프라를 확장하여, Jira 웹훅(Webhook) 트리거 시점의 시스템 및 이벤트 상태를 AI 에이전트가 자동 역추적하도록 구현하고 이슈 생성과 동시에 관련된 디버깅 로그를 추려내어 Jira 티켓 댓글로 자동 바인딩(Binding)하는 자가 진단형 장애 모니터링 인프라 구축.

## 역할

시스템 구조 설계 참여 및 주도적 개발

## 주요 업무 및 성과

### ① n8n 중심의 실시간 Jira Webhook 에이전트 파이프라인 구조화

- **웹훅 트리거 아키텍처 수립**: Jira 프로젝트 칸반 보드 내 issueType: "버그" 생성 이벤트를 실시간 수신하는 n8n Webhook Trigger 노드 아키텍처 구축
- **동적 전처리 엔진 구현**: 수신된 Jira 티켓의 메타데이터(제목, 본문 에러 텍스트, 생성 시간, 컴포넌트, App ID 등)를 n8n 컨텍스트 내에서 파싱하여 데이터 검색 범위를 동적으로 정제하는 엔진 설계.

### ② n8n 워크플로우 내 MCP(Model Context Protocol) 도구(Tools) 결합 및 데이터 바인딩

- [Neon-tools](../neon-tools/)에 선제 구축된 neon-log(서버/Access 로그 툴) 및 neo-event(이벤트 수집 툴)를 n8n 에이전트 내에 MCP 표준 도구로 노출 및 기동.
- **다이내믹 로그 추출 제어**: LLM 에이전트가 n8n 노드를 거쳐 사내 OpenSearch 인프라에 직접 다이내믹 쿼리를 질의하도록 유도하고, 에러 시점 전후의 Trace Correlation(상관관계)이 입증된 핵심 장애 로그만 선별 추출하도록 제어 흐름 설계.

### ③ 지능형 요약 및 Jira 댓글(Comment) 자동 릴레이 연동

- 추출된 핵심 원시 로그를 LLM 프롬프트 서순에 주입하여 분석 결과를 지능적으로 요약 가공.
- 가공된 데이터를 구조화하여 해당 Jira 티켓의 댓글로 실시간 자동 등록하는 인프라 완비.

## 결과

① **트러블슈팅 시간의 정량적 단축**: 개발자가 여러 모니터링 툴을 전전할 필요 없이, 버그 티켓 생성과 동시에 생성된 인컨텍스트 디버깅 데이터를 Jira 내에서 즉시 확인할 수 있는 환경을 마련함 (현재 시스템 배포 후 내부 고도화 및 실무 유효성 검증 진행 중).

## 회고

이번 프로젝트는 플랫폼 팀에 새로 합류한 시선에서 조직 내의 비효율적인 업무 방식을 포착하고, 이를 해결하기 위해 주도적으로 아키텍처를 설계하고 개발을 진행한 여정이었다. 인적 자원의 개입 없이도 시스템 장애가 발생한 맥락을 AI 에이전트가 오프체인 인프라에서 스스로 역추적하도록 유도했다.
